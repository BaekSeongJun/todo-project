# 000 · 작업 파일 형식 샘플

> 이 파일은 실제 작업이 아니라 `/tasks/` 작업 파일의 형식 예시입니다. 새 작업 파일(`001-scaffolding.md` 등)을 만들 때 이 구조를 따르세요. (근거: `docs/ROADMAP.md` 진행 원칙 7)

## 고수준 명세

- 이 작업이 **무엇을** 하는지, **왜** 필요한지를 1~2문단으로 설명합니다.
- 관련 FR ID가 있다면 명시합니다 (예: `FR-T02`, `FR-A04-1`).
- 담당 Phase와 `docs/ROADMAP.md` 상의 위치를 밝힙니다.

## 관련 파일

- `path/to/file.ts` — 이 작업에서 새로 만들거나 수정하는 파일과 역할
- `path/to/other.ts` — 참고용으로 읽어야 하는 기존 파일

## 수락 기준

- [ ] 측정 가능한 완료 조건 1 (예: 특정 API가 200을 반환한다)
- [ ] 측정 가능한 완료 조건 2 (예: `./mvnw test`가 통과한다)
- [ ] 문서 동기화 조건이 있다면 명시 (예: PRD 1.3 표 갱신)

## 구현 단계

1. 첫 번째 단계 — 무엇을 확인하거나 준비하는지
2. 두 번째 단계 — 실제 구현
3. 세 번째 단계 — 검증 (컴파일/빌드/테스트 실행)
4. 네 번째 단계 — 커밋 (저장소 3분할 규칙에 따라 올바른 저장소에서)
